# وثيقة التوثيق الهندسي المؤسسي لمنصة SentinelSQL
**بوابة تحويل النصوص إلى استعلامات SQL متعددة الوكلاء ونظام الدفاع الحتمي ضد الهلوسة**
*الإصدار 2.4.0 — مواصفات الهيكلية المؤسسية ودورة الحياة البرمجية*

---

## 1. الملخص التنفيذي وهوية النظام

### 1.1 المهمة والرؤية الهندسية
تُعد منصة **SentinelSQL** (المعروفة سابقاً باسم AegisSQL) بوابة ذاتية القيادة من الدرجة المؤسسية لتحويل استفسارات الأعمال المكتوبة باللغة الطبيعية إلى استعلامات قواعد بيانات علائقية متوافقة مع محرك **Microsoft SQL Server (T-SQL)**. صُممت المنصة وفق مبادئ الحوكمة الصارمة وسد الفجوة بين صناع القرار غير التقنيين وقواعد البيانات التشغيلية مع القضاء التام على مخاطر الأمان وتسريب البيانات والهلوسة الرياضية المصاحبة لنماذج اللغة الكبيرة (LLMs).

في الأنظمة التقليدية، يُسمح للنماذج بتوليد استعلامات وتنفيذها مباشرة، مما يؤدي إلى أربعة إخفاقات كارثية في بيئات الإنتاج:
1. **حقن الاستعلامات والتعديلات غير المصرح بها (SQL Injection & Mutation):** التلاعب بالنماذج عبر هندسة الأوامر لحذف الجداول أو تعديل المخططات أو تسريب البيانات السرية.
2. **هلوسة المخططات والأعمدة (Schema & Column Hallucination):** اختراع النماذج لجداول وأعمدة وعلاقات غير موجودة في الكتالوج الفعلي للبيانات.
3. **انتهاك حدود وصلاحيات الوصول (Privilege Escalation):** استخراج بيانات العملاء أو السجلات المالية خارج الصلاحيات الوظيفية المعتمدة للمستخدم.
4. **عشوائية المنطق المالي (Non-Deterministic Financial Logic):** وضع افتراضات عشوائية حول هوامش الأرباح ورسوم البنوك وحصص الشركاء.

تتغلب منصة SentinelSQL على هذه التحديات بشكل حتمي من خلال **جدار حماية مستند إلى شجرة الإعراب النحوي (AST-Level Firewall)**، ومنهجية **افتراض العالم المغلق (Closed-World Assumption)**، وهندسة **انعدام الثقة (Zero-Trust RBAC)**، ونظام **موزع مكون من 4 وكلاء أذكياء**.

### 1.2 بيئة التشغيل ومحاكاة البنية التحتية
- **لهجة قاعدة البيانات الأساسية:** Microsoft SQL Server (T-SQL).
- **طبقة الاتصال:** بروتوكول ODBC الأصلي عبر مكتبة `pyodbc` مع كشف تلقائي لأحدث برامج التشغيل المتاحة (`ODBC Driver 18 for SQL Server`، و`ODBC Driver 17`، و`SQL Server Native Client 11.0`).
- **كتالوج البيانات المؤسسي:** قاعدة بيانات Chinook Enterprise (مخطط تجزئة الوسائط الرقمية عالي المعاملات يشمل العملاء والفواتير وبنود الفواتير والأغاني والألبومات والفنانين والأنواع الموسيقية).
- **محرك المحاكاة البديل عالي التوافر:** محرك SQLite Mock Emulator غير متصل بالإنترنت، يتيح تشغيل المنصة واختبارها محلياً بكامل الوظائف وفحص المخططات عند تعذر الوصول إلى ملقمات SQL Server الحية دون انهيار النظام أو فقدان حالة الجلسة.
- **الهوية البصرية الصناعية:** واجهة مستخدم خالية تماماً من الرموز التعبيرية (Zero-Emoji Industrial UI) ترتكز على لوحة ألوان كحلية ورمادية مؤسسية رصينة (`#0f172a`، `#1e293b`، `#38bdf8`، `#f8fafc`).

## 2. الهندسة متعددة الوكلاء ومسار العمليات

تستبدل المنصة مسارات الأوامر الأحادية بنظام غير متزامن متعدد الوكلاء يلتزم كل وكيل فيه بحدود أمنية صارمة:

```
+-----------------------------------------------------------------------------+
|                          استقبال استفسارات المستخدم                         |
|                         (استفسارات باللغة الطبيعية)                         |
+-----------------------------------------------------------------------------+
                                       |
                                       v
+-----------------------------------------------------------------------------+
|                           الوكيل 1: موجّه النوايا                           |
|       (حارس البوابة الدلالي المصنف للنوايا بنموذج بدون تدريب مسبق)          |
|        - HELP            --> إرجاع دليل الاستخدام المزدوج باللغتين          |
|        - SECURITY_ATTACK --> حجر الهجوم الأمني وإيقاف التنفيذ               |
|        - OUT_OF_SCOPE    --> إيقاف الاستفسار كونه خارج نطاق العمل           |
|        - DATA_QUERY      --> تمرير الطلب إلى مسار الوكلاء التنفيذي          |
+-----------------------------------------------------------------------------+
                                       |
                                       v
+-----------------------------------------------------------------------------+
|                         الوكيل 2: وكيل الاستطلاع                            |
|             (فحص المخطط الحي وتصفيته وفق الصلاحيات المعرفة)                 |
|        - استعلام جداول النظام INFORMATION_SCHEMA و sys.foreign_keys         |
|        - تصفية الجداول بدقة وفق قائمة allowed_tables للمستخدم النشط          |
|        - إنشاء بطاقات المخطط ونماذج البيانات للمجال المصرح به فقط          |
+-----------------------------------------------------------------------------+
                                       |
                                       v
+-----------------------------------------------------------------------------+
|                         الوكيل 3: مبرمج لغة T-SQL                           |
|         (صياغة استعلامات T-SQL تحت افتراض العالم المغلق والقواعد المالية)   |
|        - الالتزام التام ببطاقات المخطط دون أي افتراضات خارجية (CWA)         |
|        - تطبيق قواعد الحسابات المالية المؤسسية المعتمدة (BUSINESS_RULES.md) |
|        - فرض معايير T-SQL: الأقواس المربعة [ ]، واستعلامات الدمج الصريحة     |
+-----------------------------------------------------------------------------+
                                       |
                                       v
+-----------------------------------------------------------------------------+
|                     الوكيل 4: حارس AST والناقد التنفيذي                     |
|                   (جدار الحماية الحتمي وفاحص الشجرة النحوية)                |
|        - تحليل بنية الاستعلام النحوية عبر sqlglot لهيكل tsql                |
|        - حظر التعديلات: DROP, DELETE, INSERT, UPDATE, ALTER, TRUNCATE       |
|        - حظر الإجراءات الإدارية: xp_cmdshell, sp_executesql, EXEC           |
|        - مطابقة عقد الجداول exp.Table مع القائمة البيضاء لدور المستخدم      |
|        - كشف الأعمدة المهلوسة وتفعيل حلقة التصحيح الذاتي التكرارية          |
+-----------------------------------------------------------------------------+
                                       |
                                       v
+-----------------------------------------------------------------------------+
|                       وكيل التصور الذاتي وبوابة العرض                       |
|        - تنفيذ الاستعلام الآمن للقراءة فقط على ملقم SQL أو المحاكي          |
|        - إنشاء رسوم بيانية تفاعلية داكنة عبر مكتبة Plotly                   |
|        - عرض النتائج في 4 تبويبات صناعية: المؤشرات، الجدول، SQL، والتشخيص   |
+-----------------------------------------------------------------------------+
```

### 2.1 موجّه النوايا (IntentRouter)
يعمل كمحيط دفاعي أولي، ويستخدم نموذج تصنيف دلالي مباشر لفحص الاستفسارات مقابل نطاق أعمال Chinook:
1. `HELP` / `CAPABILITY_HELP`: استفسارات التعريف بالنظام أو المساعدة. يعرض فوراً دليلاً ترحيبياً مؤسسياً باللغتين العربية والإنجليزية مع 3 نماذج لاستفسارات مسموحة؛ دون توليد أي SQL.
2. `DATA_QUERY`: استفسارات تشغيلية مشروعة تقع ضمن اختصاص قاعدة البيانات، ويتم توجيهها لمسار الوكلاء.
3. `OUT_OF_SCOPE`: أسئلة عامة (رياضة، طقس، طبخ، برمجة عامة). يوقف الطلب مع رسالة `[DOMAIN BOUNDARY EXCEPTION]`.
4. `SECURITY_ATTACK`: محاولات كسر الحماية أو تجاوز الأوامر أو تعديل البيانات. يتم حظرها مع رسالة `[SECURITY_QUARANTINE_REJECTION]`.

### 2.2 وكيل الاستطلاع (ReconnaissanceAgent)
يقوم بفحص وتوليد مخطط قاعدة البيانات اللحظي، واستخراج أسماء الحقول وأنواع البيانات والمفاتيح الأساسية والعلاقات الأجنبية. تتم التصفية على أساس دور المستخدم الموثق، بحيث لا يتم تسريب أي جدول خارج صلاحيات المستخدم في سياق النموذج.

### 2.3 وكيل البرمجة (SQLCoderAgent)
يقوم بصياغة استعلامات T-SQL دقيقة بالاعتماد الحصري على بطاقات المخطط المزودة تحت مبدأ **العالم المغلق (Closed-World Assumption)**. يدمج الوكيل تلقائياً الصيغ المالية المعتمدة، ويلتزم بأقواس التمييز `[Table].[Column]` وعبارات التحديد `TOP`.

### 2.4 حارس AST والناقد التشغيلي (ASTGuardianAgent & RuntimeCriticAgent)
يوفر صمام الأمان الحتمي والنهائي للمنصة:
- **تحليل شجرة البنية النحوية (AST):** فحص الاستعلام باستخدام مكتبة `sqlglot`.
- **شلل التعديل والتخريب:** منع أي استعلام يحتوي على أوامر حذف أو تعديل أو إنشاء أو إجراءات مخزنة.
- **عزل الصلاحيات على مستوى الجداول:** التحقق من كل عقدة جدول `exp.Table` في الشجرة النحوية ورفض الاستعلام فوراً إذا تضمن جدولاً غير مصرح به.
- **حظر الأعمدة الوهمية والتعافي الذاتي:** التأكد من وجود الأعمدة المستعلمة في المخطط الحقيقي، وإذا أصدرت قاعدة البيانات خطأ تنفيذياً يتم تمرير رسالة الخطأ لوكيل البرمجة لإعادة الصياغة خلال 3 محاولات كحد أقصى.

### 2.5 المصور الذاتي للبيانات (AutonomousVisualizer)
يقوم بتحليل مخرجات البيانات الناتجة في جدول `pandas.DataFrame`، ويختار تلقائياً نوع الرسم البياني المناسب (أعمدة للتجميعات، خطوط للمؤشرات الزمنية، دوائر للنسب المئوية) بتصميم داكن متناسق مع الواجهة.

## 3. مواصفات التحكم في الوصول القائم على الأدوار (RBAC)

تفرض المنصة عزلاً صارماً لامتيازات الجداول عبر كافة الطبقات البرمجية:

| البعد / المعيار | دور محلل المبيعات (`sales_analyst`) | دور مسؤول المخزون والكتالوج (`inventory_lead`) |
| :--- | :--- | :--- |
| **المسمى الوظيفي** | رئيس استخبارات المبيعات التجارية | رئيس إدارة الكتالوج والوسائط |
| **بيانات الدخول للاختبار**| `sales_analyst` / `Sales@2026!` | `inventory_lead` / `Ops@2026!` |
| **الجداول المصرح بها حصرياً**| `Customer`، `Invoice`، `InvoiceLine` | `Track`، `Album`، `Artist`، `Genre`، `MediaType` |
| **الجداول المحظورة** | كافة جداول الكتالوج والمقاطع الموسيقية | كافة جداول الفواتير والعملاء والحسابات |
| **الصلاحية المالية** | وصول كامل لحساب الإيرادات والأرباح والرسوم | حظر كامل: لا يمكن استعراض أي بيانات مالية |
| **استطلاع المخطط** | بطاقات المخطط لـ 3 جداول تجارية فقط | بطاقات المخطط لـ 5 جداول كتالوج فقط |
| **الاستعلامات المتداخلة** | حظر فوري من جدار الحماية AST | حظر فوري من جدار الحماية AST |

## 4. القواعد الحسابية والمالية المؤسسية

وفقاً لوثيقة حوكمة الأعمال الرسمية `BUSINESS_RULES.md`، يتم احتساب كافة المؤشرات المالية وفق المعادلات التالية:

| المؤشر المالي | المعادلة الرياضية | صياغة استعلام T-SQL المعتمدة | الوصف التشغيلي |
| :--- | :--- | :--- | :--- |
| **إجمالي الإيرادات (Gross Revenue)** | $\sum (\text{UnitPrice} \times \text{Quantity})$ | `ROUND(SUM([UnitPrice] * [Quantity]), 2)` | إجمالي قيمة المبيعات المفوترة قبل خصم الرسوم أو حصص الشركاء. |
| **رسوم المعالجة البنكية (Bank Fee)** | $\text{Gross Revenue} \times 0.025$ | `ROUND(SUM([UnitPrice] * [Quantity]) * 0.025, 2)` | نسبة 2.5% تقتطعها بوابة الدفع والبنك المستحوذ عن كل معاملة. |
| **صافي الإيرادات (Net Revenue)** | $\text{Gross Revenue} \times 0.975$ | `ROUND(SUM([UnitPrice] * [Quantity]) * 0.975, 2)` | الإيراد المتبقي للمؤسسة بعد خصم رسوم البنك. |
| **حصة الشركاء وحقوق الأداء (Partner Share)** | $\text{Net Revenue} \times 0.70$ | `ROUND(SUM([UnitPrice] * [Quantity]) * 0.975 * 0.70, 2)` | نسبة 70% من صافي الإيرادات تدفع للفنانين والشركات المنتجة. |
| **صافي ربح الشركة (Company Net Profit)** | $\text{Net Revenue} \times 0.30$ | `ROUND(SUM([UnitPrice] * [Quantity]) * 0.975 * 0.30, 2)` | نسبة 30% من صافي الإيرادات تمثل الأرباح المحتجزة للشركة. |

## 5. سجل الحوادث الهندسية ومعالجة الأعطال

خلال عمليات تعزيز جاهزية الإنتاج والنشر، تم تشخيص وحل أربعة أعطال حرجة أثرت على استقرار التطبيق:

### 5.1 الحادث الأول: إزالة استدعاء التغذية القديم لقاعدة بيانات SQLite
- **العَرَض:** ظهور خطأ `NameError: name 'seed_database' is not defined` عند إقلاع التطبيق.
- **السبب الجذري:** بقاء استدعاء قديم من أداة بذر البيانات (`utils/db_seeder.py`) بعد اكتمال التحول إلى ملقمات Microsoft SQL Server.
- **الحل الهندسي:** إزالة الاستدعاء المتقادم بالكامل والاعتماد حصرياً على `MSSQLDatabaseEngine` الذي يتولى فحص المخطط الحي والتبديل التلقائي إلى محاكي SQLite المحلي عند تعذر الاتصال بالملقم الحي.

### 5.2 الحادث الثاني: معالجة خطأ تفكيك القيم المرجعة في `test_connection`
- **العَرَض:** خطأ `ValueError: too many values to unpack (expected 2)` عند السطر 205 في ملف `app.py`.
- **السبب الجذري:** تحديث دالة فحص الاتصال لتقيس زمن الاستجابة (Latency) وإرجاع ثلاث قيم `(is_ok, message, latency)` بينما كانت واجهة المستخدم تفكك قيمتين فقط.
- **الحل الهندسي:** إعادة كتابة معالج تفكيك القيم ليدعم تفكيك قيمتين أو ثلاث قيم بمرونة ودون تعطل واجهة المستخدم.

### 5.3 الحادث الثالث: معالجة خطأ الخصائص المفقودة في `IntentResult`
- **العَرَض:** خطأ `AttributeError: 'IntentResult' object has no attribute 'response'` (و `'reason'`) عند السطر 388 في `app.py`.
- **السبب الجذري:** تعريف الحقول بأسماء `.response_message` و `.reasoning` في الفئة الأصلية، بينما كانت بعض الأجزاء البرمجية تستدعي الخصائص المختصرة `.response` و `.reason`.
- **الحل الهندسي:** إضافة خصائص بديلة (@property) مع دوال الضبط (setter) لتوفير التوافق الكامل، وإحاطة تصنيف النوايا بكتلة `try-except` ترجع القيمة الافتراضية `DATA_QUERY` عند حدوث أي استثناء دون إيقاف جلسة المستخدم.

### 5.4 الحادث الرابع: معالجة خطأ الاستيراد عند الإقلاع بالسطر 15
- **العَرَض:** خطأ `ImportError: cannot import name 'IntentResult' from 'agents.intent_router'` في السطر 15.
- **السبب الجذري:** غياب قائمة التصدير الصريحة `__all__`، وعدم تمييز الفئة بمحدد `@dataclass`، وتباين مسار التشغيل `sys.path` في بيئة الحاويات المعزولة على Streamlit Cloud.
- **الحل الهندسي:** تحويل `IntentResult` إلى فئة بيانات معتمدة `@dataclass`، وتصدير كافة الرموز عبر `__all__`، وإتاحة استدعاء الفحص بالطرق الثابتة والمباشرة، وإدراج كود تهيئة ديناميكي لمسار `sys.path` أعلى ملف `app.py` مع توفير كتل استيراد احتياطية متعددة المستويات.

## 7. النشر السحابي وخطوط التكامل والنشر المستمر (CI/CD)

### 7.1 حزمة النشر الإنتاجية المعزولة (`deploy_bundle/`)
لضمان سرعة إقلاع المنصة وخلو بيئة الاستضافة من الملفات الزائدة، تم تخصيص مجلد نشر إنتاجي مستقل:
- **الملفات والمكونات المعتمدة:**
  - `deploy_bundle/app.py`: بوابة واجهة المستخدم الرئيسية.
  - `deploy_bundle/core/`: الوحدات الأساسية للمصادقة وقواعد البيانات والإعدادات.
  - `deploy_bundle/agents/`: كافة الوكلاء الأذكياء وموجه النوايا والمصور.
  - `deploy_bundle/tools/`: أدوات فحص وتشخيص ملقمات SQL Server.
  - `deploy_bundle/requirements.txt`: متطلبات التشغيل الأساسية.
- **الملفات المستبعدة تماماً:** البيئات الافتراضية، وقواعد البيانات المؤقتة، والملفات السرية `.env`، والملفات المترجمة `__pycache__`.

### 7.2 النشر التلقائي عبر Streamlit Cloud
ترتبط بيئة النشر بمستودع GitHub عبر فرع `main`. عند إرسال أي تحديث تم التحقق منه، يقوم خط الإنتاج الآلي بإعادة بناء الحاوية البرمجية وتحديث الخادم السحابي فورياً ودون أي توقف في الخدمة.
