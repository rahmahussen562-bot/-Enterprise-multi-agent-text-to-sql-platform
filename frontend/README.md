# SentinelSQL enterprise product experience

React/TypeScript SPA with Vite, Tailwind's Vite plugin, accessible Radix primitives, Lucide icons, Recharts and a virtualized financial result grid. All dependencies, caches, temporary files and build outputs stay inside `D:/BIRD-Interact/frontend`.

## Setup and development

```powershell
Set-Location D:\BIRD-Interact\frontend
. .\tools\use-d-runtime.ps1
npm install
npm run dev
```

For Command Prompt:

```bat
cd /d D:\BIRD-Interact\frontend
call tools\use-d-runtime.cmd
npm install
npm run dev
```

Open `http://localhost:5173`. Vite forwards HTTP and WebSocket `/api` requests to `http://127.0.0.1:8000`. Start the backend separately:

```powershell
Set-Location D:\BIRD-Interact\deploy_bundle
. .\tools\use_d_runtime.ps1
# Provision your own credentials once; skip if already provisioned.
.\.venv\Scripts\python.exe -B tools\bootstrap_api.py
# Optional local Chinook evaluation only; production needs its SQL Server settings.
$env:SENTINEL_DEMO_MODE = '1'
.\.venv\Scripts\python.exe -B tools\run_api.py
```

Production has no demo passwords. The sign-in card's persona selector describes the workspace; authorization always comes from the server's returned session. Tokens and result data are kept in memory, never browser storage. Refreshing the page requires authentication again. Only the language preference is stored locally.

## Build, tests and generated contracts

```powershell
npm run generate:api
npm run check:api
npm test
npm run build
```

`npm test` also saves its JUnit report at `.runtime/frontend-tests.xml`. For reproducible CI installation, use `npm ci` with the committed `package-lock.json` after loading the D-drive runtime script.

Build output is `dist/`; caches are `.runtime/`. The project `.npmrc` pins npm cache/prefix/log paths to this D-drive workspace. `tools/run.mjs` also redirects temporary files before starting Vite or tests. A self-contained Node runtime is provided at `.runtime/node`; the runtime setup script places it first on PATH. Vite's current Node requirement is documented at [vite.dev](https://vite.dev/guide/).

`openapi.json` is the additive Phase 4 contract exported by `deploy_bundle/tools/export_phase04_openapi.py`. Existing REST paths, query requests and output shapes remain unchanged; the role enumeration adds three banking personas and schema dialect adds `postgres`. `src/api/generated.ts` is generated by openapi-typescript; client request/response models derive from it. Phase 3 adds `GET /api/v1/health` and protected `GET /api/v1/schema` to the approved Phase 2 routes. The health response describes API/AST availability and current worker occupancy; it does not claim database availability or a fabricated uptime percentage.

## Product behavior

- The landing page includes selectable adversarial scenarios, an animated SVG pipeline, four interactive agent stages, actual API health checks, and the secure role portal. The policy sandbox is an explicitly labeled local illustration with fixed sample outcomes. Real query validation happens in the authenticated backend.
- The workspace fetches only server-filtered tables, columns and relationships. Other domains remain hidden. SQL and exception payloads render as text rather than HTML.
- Each request is classified before execution. Live mode uses the authenticated WebSocket; REST mode uses `/query/execute` and then retrieves owned audit records. The verified SQL panel and correction diffs use server output.
- WebSocket frames are queued with bounds, durable events are deduplicated and replayed in sequence, and row batches are replaced by their offset. Final results wait for missing audit events to be recovered; unresolved gaps fail closed. Reconnect subscribes to an acknowledged job and never automatically resubmits an ambiguous query. Closing an initiating socket cancels the server query under the Phase 2 contract; reconnect therefore may show its cancelled result.
- The grid uses viewport virtualization, client sorting and 100-row pages. Decimal strings sort exactly using scaled BigInt comparisons. CSV escapes formula-like strings; Excel stores decimal strings as text to preserve precision. Exports include all sorted rows, independent of the visible page.
- Charts use actual results and load separately. Decimal chart values are approximations, with exact values retained in the grid/export. No financial values or certification badges are fabricated.
- English/Arabic controls switch document and Radix direction. SQL stays LTR. Database identifiers, server event messages and the approved English quick-query examples retain their technical source language. Optional dictation uses the browser's speech-recognition provider only after a user click and browser permission; provider availability and privacy behavior depend on the browser.

Banking accounts select the PostgreSQL/FinCore engine on the server; the original two roles retain T-SQL/Chinook compatibility. The portal exposes all five personas without letting browser selection grant access. Schema and SQL panels use the server dialect. Banking shortcuts use approved registry v1 English requests, including in the Arabic layout; unknown filters and financial formulas fail closed. See `D:/BIRD-Interact/deploy_bundle/docs/FINCORE_SCHEMA.md` for migration and private `SENTINEL_PG_AUTH_FILE` provisioning. PostgreSQL access is never inferred from demo mode. Native PostgreSQL integration is verified locally; cloud deployment remains a subsequent phase.

## Deployment handoff

For static hosting, build with `VITE_API_URL=/api/v1` behind a same-origin API gateway, or set an explicit HTTPS API origin before building. Configure that origin's CORS/WebSocket allowlist to include the actual frontend domain. The included Pages `_redirects` and `_headers` are deployment artifacts; API routing and Cloudflare deployment belong to the following phase. Tighten `connect-src` to the production API origin when it is chosen. HTTPS and secure WebSocket connections are required for deployed sessions.

Dependency patterns follow the official [Tailwind Vite integration](https://tailwindcss.com/docs/installation/using-vite) and [Radix accessibility model](https://www.radix-ui.com/primitives/docs/overview/accessibility).
